# Design — Program sheet new columns: People, Format, Info_md, Title

## Overview

All logic stays in `scripts/build-program.js` (Node 18+, zero dependencies).
Four new canonical fields — `title`, `speakers` (fed by People), `format`,
`infomd` — flow from header aliases through record validation and `fold()`
into three render targets: the schedule include, `program.json`, and a new
generator that writes one abstract page per format plus the active program
menubar. Generated files carry a banner so pruning can never touch
human-authored files.

## Affected components

| File / module | Change |
| --- | --- |
| `scripts/build-program.js` | Header aliases; People parser; Format normalization + Title validation; fold carries new talk fields; schedule renderer adds format pill, people span, deep links; new abstract-page and menubar generators with banner-guarded pruning |
| `assets/css/program.css` | New `.talk__format` pill and `.talk__link` styles |
| `fixtures/schedule.csv` | Add the four columns with representative values |
| `.github/workflows/build-program.yml` | Commit step covers the new generated paths, including deletions |
| `_data/menus/program.yml` | New, script-generated (see deviation note) |
| `pages/program/abstracts/<slug>.md` | Script-generated abstract pages |
| `_includes/program-schedule.html`, `_data/program.json` | Regenerated by the daily Action after merge (decision 16) |
| `README.md` + script docstring | Document the new columns and artifacts |

## Detailed design

### 1. Header aliases (`HEADER_ALIASES`, `normalizeHeader`)

```js
title: 'title',          // was 'session' — superseded per Story 3
people: 'speakers',      // same canonical field as Speakers
format: 'format',
infomd: 'infomd',        // "Info_md" normalizes to "infomd" (non-letters stripped)
```

`sessiontitle` keeps mapping to `session`. Repointing `title` is safe: the
live sheet and fixture both use a "Session" header, never "Title".

### 2. Format vocabulary (`FORMATS`)

A lookup keyed by lowercased trimmed value:

| Sheet value | Label (pill) | Page title | Permalink | Slug/file |
| --- | --- | --- | --- | --- |
| Bird of a Feather | Bird of a Feather | Birds of a Feather | `program/bofs/` | `bofs` |
| Keynote | Keynote | Keynotes | `program/keynotes/` | `keynotes` |
| Paper | Paper | Papers | `program/papers/` | `papers` |
| Plenary | Plenary | Plenaries | `program/plenaries/` | `plenaries` |
| Poster | Poster | Posters | `program/posters/` | `posters` |
| Talk | Talk | Talks | `program/talks/` | `talks` |
| Workshop | Workshop | Workshops | `program/workshops/` | `workshops` |
| Other | — (none) | — (no page) | — | — |

`normalizeFormat(raw)` returns `null` for an empty cell, the matched entry
for a known value, and the Other entry for "Other" **and any unrecognized
value** (decision 17). The raw cell text is kept alongside for
`program.json`.

### 3. Validation (after `toRecords`, before `fold`)

For every event record (`rec.talk` non-empty): if its format maps to a
page format (the seven non-Other rows above) and `rec.title` is empty,
collect `row N: Format "Paper" requires a Title`. After the scan, throw one
Error listing every offender — a program chair fixes all gaps in one pass.
Session records never read `title`/`format`/`infomd`/`speakers` (Story
criteria: event-level only), so stray values there are inert, not errors.

### 4. People parsing (`parsePeople`)

Split the cell on commas; strip a leading `and ` from each segment; split
any remaining segment on `/\s+and\s+/`; trim; drop empties. Handles
"A, B and C", "A, B, and C", and "A and B". Known limitation (accepted): a
single name legitimately containing " and " cannot be distinguished from
two names.

Display always uses the cell **as typed** (schedule and abstract byline) —
editors control phrasing, and legacy `Speakers` cells render byte-identical
(Story 7). The parsed array goes only to `program.json` (`people`).

### 5. `fold()` additions

Talk entries gain: displayed `title` (`rec.title || rec.talk`),
`peopleRaw`, `people[]`, `formatRaw`, the matched `FORMATS` entry, and
`infoMd`. Session objects are untouched. After folding, a single pass in
schedule traversal order (day → slot → room-ranked session → order-sorted
talks) assigns each page-format event an `anchor`: `slugify(title)`
(lowercase, non-alphanumerics → hyphens, trimmed), deduplicated per page
with `-2`, `-3` suffixes. That same traversal order is the entry order on
each abstract page — stable and deterministic.

### 6. Schedule rendering (`renderSession`)

The talk `<li>` becomes:

```html
<li class="talk">
  <span class="talk__format">Paper</span>            <!-- page formats only -->
  <span class="talk__title">…title…</span>           <!-- or wrapped in a link -->
  <span class="talk__speakers">…people as typed…</span>
</li>
```

- Format pill renders only for the seven page formats — Other, unknown,
  and empty render nothing (Stories 2/3).
- When the event has non-empty `infoMd` **and** a page format, the title is
  wrapped: `<a class="talk__link" href="{{ 'program/<slug>/' | relative_url }}#<anchor>">`.
  The include is processed by Liquid when Jekyll includes it, so
  `relative_url` keeps links correct under the `/usrse26` baseurl and in
  CircleCI previews. Otherwise the title renders unlinked, as today.
- All text passes through the existing `esc()`.

CSS: `.talk__format` — small uppercase pill (bordered, `--program-accent`,
sized like `.session__eyebrow`) clearly distinct from the muted
`.talk__speakers`; `.talk__link` — accent-colored underlined link that
keeps the title weight. Rows with none of the new values produce identical
markup to today (Story 6/7).

### 7. `program.json`

Talk objects stay `{ title, speakers }` and append new fields **only when
non-empty** so legacy CSVs produce byte-identical JSON (Story 7):

- `title` — the displayed title (Title cell when present, else Talk cell)
- `speakers` — the raw People/Speakers cell, as today
- `people` — parsed name array
- `format` — the Format cell as typed (unknown values preserved)
- `infoMd` — the raw Markdown string, never HTML (decision 6)
- `href` — site-relative deep link `program/<slug>/#<anchor>` when one is
  rendered on the schedule

### 8. Abstract pages (`pages/program/abstracts/<slug>.md`)

One file per format having ≥1 event. Front matter mirrors
`pages/program/program.md`, followed by the generator banner:

```markdown
---
layout: page
title: Papers
description: Paper abstracts at USRSE'26
menubar: program
permalink: program/papers/
set_last_modified: true
---
<!-- Generated by scripts/build-program.js — do not edit by hand. -->
```

Each entry, in schedule traversal order, matching the USRSE'25 entry style
(h2 title, italic byline — e.g. us-rse.org/usrse25/program/bofs/):

```markdown
## AquiLLM: Evaluating Faithfulness… {#aquillm-evaluating-faithfulness}

_Bernie Boscoe, Tuan Do, and Jack Stark_

…Info_md content…
```

- The kramdown `{#anchor}` header IAL pins the anchor the schedule links
  to — no reliance on kramdown's auto-ID algorithm.
- The byline line is omitted when the event has no People; the body is
  omitted when Info_md is empty (entry still listed — Story 5).
- Info_md, the title, and the byline are HTML-escaped (`&`, `<`, `>`)
  before writing. kramdown renders `&lt;script&gt;` as literal text, so raw
  HTML can never pass through, while Markdown links/emphasis/code survive
  untouched (Story 4).

**Pruning:** after writing, scan `pages/program/abstracts/*.md`; delete any
file that contains the generator banner but is not in the active slug set
(logged as `removed`). Files without the banner — the `.tbd` placeholders,
any human-authored page — are never touched.

### 9. Menubar — deviation from the requirements' path

Requirements name `_data/menus/hidden/program.yml`, but
`_includes/menubar.html` resolves `site.data.menus[page.menubar]`, so only
`_data/menus/program.yml` is live — `hidden/` is deliberate parking that
Jekyll's menubar never reads. **The script therefore generates the active
`_data/menus/program.yml`** (flagged for review as an intentional
deviation):

```yaml
# Generated by scripts/build-program.js — do not edit by hand.
- label: Program
  items:
    - name: Full Program
      link: program/
    - name: Papers
      link: program/papers/
    …
```

"Full Program" always leads; format entries follow in the vocabulary order
of §2. The file is emitted wholesale by a trivial fixed-shape writer (no
YAML library), through `writeIfChanged`. When no abstract pages exist the
file is deleted if it carries the banner — the menu reverts to today's
hidden state, and a legacy CSV never creates it (Story 7).
`_data/menus/hidden/program.yml` stays untouched as the human-owned seed.

### 10. Workflow (`build-program.yml`)

The commit step's `git diff --quiet --` guard and staging extend to
`pages/program/abstracts` and `_data/menus/program.yml`, and staging
becomes `git add -A -- <paths>` so pruning deletions are committed too.
Permitted by the out-of-scope carve-out ("beyond committing any newly
generated pages").

### 11. Fixture and docs

`fixtures/schedule.csv` gains the four columns, exercising: multiple
formats (so several pages generate), Oxford-comma and "and" People
variants, an Other row with and without Title, an empty-format legacy row,
and a multi-paragraph quoted Info_md (the CSV parser already handles
embedded newlines). Every fixture row stays valid — the build must
succeed; the missing-Title error path is exercised by a deliberate
temporary edit during implementation, not a committed fixture. The script
docstring's expected-columns list and the README build section are updated.

### 12. Keeping live artifacts intact (decision 16)

A fixture build overwrites `_includes/program-schedule.html`,
`_data/program.json`, abstract pages, and the menubar with fixture-derived
content. Implementation verifies output, then restores those paths
(`git checkout -- …` / delete untracked generated files) before
committing; the daily Action regenerates everything from the live sheet
after merge. The tasks phase encodes this as an explicit step.
