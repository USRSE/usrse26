# Requirements — collapsible abstracts

Status: approved

## Summary

The abstract pages under `pages/program/abstracts/` are generated by
`renderAbstractPage()` in `scripts/build-program.js` (lines 581–605) as a flat
Markdown run: `## Title {#anchor}`, an italic byline, the abstract body, and a
`------` rule between entries. Every abstract is permanently expanded, so
`pages/program/abstracts/talks.md` already renders 374 lines of prose and will
grow as the Schedule sheet fills in. Finding a talk means scrolling past every
abstract that precedes it.

USRSE'25 solved this with a Bootstrap 4 accordion (`<div id="accordion">` →
`.card` → `button.btn-link[data-toggle="collapse"]`), showing the title and a
bold byline collapsed and the abstract inside the panel. That markup still
exists in this repo as the inactive `pages/program/abstracts/*.tbd`
placeholders from the previous cycle.

This feature brings the same affordance to USRSE'26 with updated styling and a
modern, JS-light implementation: the generator emits native
`<details>`/`<summary>` disclosure blocks, a new `assets/css/abstracts.css`
styles them in the idiom of `assets/css/program.css`, and a small
`assets/js/abstracts.js` handles deep links, expand/collapse all, and printing.

The schedule side is untouched. `assignAnchors()` (lines 409–427) already pins
a stable anchor per entry, and `renderSession()` (lines 471–483) already deep-
links titles into `program/<format>/#<anchor>`. Those anchor strings must keep
working, which is the single hardest constraint here: a link into a collapsed
panel has to open it.

## User stories

### Story 1 — Scan the list of entries

As a conference attendee browsing the Talks page, I want to see a compact list
of titles and speakers so that I can find the entry I care about without
scrolling through every abstract.

**Acceptance criteria**

- WHEN an abstract page is rendered, THE system SHALL present each entry as a
  collapsed disclosure row showing the entry title and, when the sheet supplies
  People, the byline.
- WHEN an abstract page is rendered, THE system SHALL keep every entry
  collapsed by default.
- WHEN an abstract page is rendered, THE system SHALL list entries in the same
  order the current generator uses (the `collectAbstracts()` traversal order:
  day → slot → room-ranked session → order-sorted talk).
- WHEN an entry has no People value, THE system SHALL render the row with the
  title alone rather than an empty byline.

### Story 2 — Read one abstract

As an attendee, I want to expand a single entry to read its abstract so that I
can evaluate a talk without losing my place in the list.

**Acceptance criteria**

- WHEN a reader activates a collapsed row, THE system SHALL reveal that entry's
  abstract body and leave every other entry in its current state.
- WHEN an entry's Event Description contains Markdown, THE system SHALL render
  it with the same kramdown pipeline the rest of the site uses.
- WHEN an entry's Event Description contains raw HTML or Liquid syntax, THE
  system SHALL render it as literal text rather than executing it.
- WHEN a reader navigates the page by keyboard, THE system SHALL make each row
  reachable by Tab and operable by Enter or Space, with a visible focus
  indicator.

### Story 3 — Follow a deep link from the schedule

As an attendee reading the program schedule, I want a talk title link to take
me straight to that talk's abstract so that the schedule stays my entry point.

**Acceptance criteria**

- WHEN a reader loads an abstract page with a URL fragment matching an entry,
  THE system SHALL open that entry and scroll it into view clear of the fixed
  navbar.
- WHEN the fragment changes while the page is already loaded (a second link to
  the same page), THE system SHALL open the newly targeted entry.
- WHEN the anchor strings are compared before and after this change, THE system
  SHALL produce identical values, so existing links, `_includes/program-schedule.html`
  and `_data/program.json` need no corresponding edit.

### Story 4 — Entries with no abstract

As an attendee, I want entries that have no description yet to read as plain
rows so that I never open a panel onto nothing.

**Acceptance criteria**

- WHEN an entry has People but no Event Description, THE system SHALL render a
  non-collapsible row carrying the title and byline, with no disclosure control.
- WHEN a non-collapsible row is the target of a deep link, THE system SHALL
  still scroll it into view.
- WHEN an entry has an Event Description consisting only of whitespace, THE
  system SHALL treat it as absent.

### Story 5 — Expand and collapse everything

As an attendee who wants to read or search the whole page, I want a single
control to open every entry so that browser find-in-page and skim-reading work
across the full set.

**Acceptance criteria**

- WHEN JavaScript is available, THE system SHALL show an "Expand all" control
  above the entry list.
- WHEN a reader activates that control, THE system SHALL open every collapsible
  entry on the page and relabel the control to "Collapse all".
- WHEN a reader activates the control while it reads "Collapse all", THE system
  SHALL close every entry and relabel it to "Expand all".
- WHEN every entry becomes open or closed by other means (individual toggling),
  THE system SHALL keep the control's label consistent with the page state.

### Story 6 — Print the page

As a program committee member assembling a printed or PDF program, I want every
abstract to appear in the output so that nothing is silently dropped.

**Acceptance criteria**

- WHEN a reader prints an abstract page, THE system SHALL include every entry's
  abstract body in the printed output regardless of its on-screen state.
- WHEN printing finishes, THE system SHALL restore each entry to the state it
  had before printing began.
- WHEN a reader prints an abstract page, THE system SHALL omit the expand/
  collapse control from the printed output.

### Story 7 — Work without JavaScript

As a reader with JavaScript disabled or still loading, I want the page to
remain usable so that the content is never gated behind a script.

**Acceptance criteria**

- WHEN JavaScript is unavailable, THE system SHALL still allow each entry to be
  expanded and collapsed by pointer or keyboard.
- WHEN JavaScript is unavailable, THE system SHALL NOT display the expand/
  collapse-all control.
- WHEN JavaScript is unavailable, THE system SHALL still render every title and
  byline in the collapsed rows.

### Story 8 — Keep the build honest

As a maintainer re-running the generator, I want the new output to behave like
the rest of the generated artifacts so that scheduled rebuilds stay quiet and
hand-authored files stay safe.

**Acceptance criteria**

- WHEN the generator runs against unchanged input, THE system SHALL report the
  abstract pages as unchanged and write nothing.
- WHEN the generator writes an abstract page, THE system SHALL include the
  existing `PAGE_BANNER` marker so pruning continues to distinguish generated
  pages from the hand-authored `.tbd` placeholders.
- WHEN a format disappears from the sheet, THE system SHALL continue to prune
  its banner-carrying page and update `_data/menus/program.yml` exactly as
  today.
- WHEN the generator runs with `--file fixtures/schedule.csv`, THE system SHALL
  exit zero and produce pages that Jekyll builds without error.

## Out of scope

- The program schedule page itself (`_includes/program-schedule.html`,
  `renderSession()`, `renderHTML()`) — its markup and styling are unchanged.
- The shape of `_data/program.json`.
- The Google Sheet columns, `HEADER_ALIASES`, `fold()`, and the `FORMATS`
  vocabulary.
- Search indexing (`pages/search.html`, `assets/js/search.js`) — no work is
  planned to teach the Lunr index about collapsed content.
- Retiring or updating the inactive `pages/program/abstracts/*.tbd`
  placeholders.
- Any change to the site-wide Bootstrap/jQuery/Alpine bundle in
  `_includes/footer-scripts.html` or `_includes/head.html`.
- Animating the open/close transition.

## Resolved decisions

- **Mechanism:** native `<details>`/`<summary>` with custom CSS, not the
  Bootstrap 4 collapse pattern USRSE'25 used. Native disclosure needs no JS for
  the toggle itself, is keyboard- and screen-reader-accessible without ARIA
  wiring, is expanded automatically by browser find-in-page, and leaves styling
  fully open for the "updated styling" goal.
- **Open behavior:** independent toggles. Any number of entries may be open at
  once; opening one never closes another. (USRSE'25 used `data-parent`, a
  single-open accordion.)
- **Collapsed row content:** title and byline, matching USRSE'25.
- **Expand all / Collapse all:** included.
- **Printing:** all entries forced open.
- **Sidebar table of contents:** dropped. Generated abstract pages stop setting
  `menubar_toc: true` — a page of collapsed titles is itself the contents list,
  and the sidebar TOC would duplicate it.
