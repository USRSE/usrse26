# Design — collapsible abstracts

## Overview

`renderAbstractPage()` (`scripts/build-program.js:581-605`) stops emitting a
flat Markdown run and emits a `<div class="abstracts">` wrapper containing one
block per entry: a native `<details>` when the entry has an Event Description,
a plain `<div>` when it does not. Abstract bodies keep going through kramdown
by reusing the Liquid-capture pattern `renderSession()` already uses for
session descriptions (`:465`), so no HTML-in-Markdown parsing rules are
involved. The anchor strings produced by `assignAnchors()` (`:409-427`) are
untouched — only the element that carries the `id` moves from the entry's `<h2>`
to its `<details>`/`<div>` wrapper, so `_includes/program-schedule.html` and
`_data/program.json` need no corresponding edit.

Two new hand-written assets support the markup: `assets/css/abstracts.css`,
written in the idiom of `assets/css/program.css` (scoped token block, explicit
theme-neutralization, padding for spacing), and `assets/js/abstracts.js`, a
small dependency-free script that reveals deep-link targets, drives the
expand/collapse-all control, and forces every panel open for printing. Each
generated page links both, mirroring how `pages/program/program.md:12-13` loads
`program.css` with a `site.time` cache-buster.

The disclosure toggle itself is pure browser behavior. JavaScript only adds the
three things native `<details>` cannot do on its own, which is what keeps
Story 7 (no-JS) satisfiable.

## Detailed design

### 1. Page shape

```
---
layout: page
title: Talks
description: Talk abstracts at USRSE'26
menubar: program
permalink: program/talks/
set_last_modified: true
---
<!-- Generated by scripts/build-program.js — do not edit by hand. -->
<link rel="stylesheet" href="{{ site.baseurl }}/assets/css/abstracts.css?v={{ site.time | date: '%s' }}">

<div class="abstracts">
  <div class="abstracts__toolbar" hidden>
    <button class="abstracts__toggle-all" type="button">Expand all</button>
  </div>
  … entries …
</div>

<script src="{{ site.baseurl }}/assets/js/abstracts.js" defer></script>
```

`menubar_toc: true` is dropped (Resolved decision). `menubar: program` stays, so
the program menubar built by `writeMenubar()` (`:648-669`) still renders.

The `?v={{ site.time | date: '%s' }}` cache-buster is Liquid, not a build-time
value, so the file's bytes stay stable across generator runs and
`writeIfChanged()` (`:696-706`) still reports `unchanged` — Story 8.

`defer` on the script is required: it is emitted at the end of the page body,
but `_layouts/default.html` renders `_includes/footer-scripts.html` after the
content, and `defer` keeps ordering predictable regardless.

### 2. Entry markup — collapsible

For an entry with a non-empty `infoMd`:

```html
  <details class="abstract" id="lz-oracle-an-ai-assisted-knowledge-retrieval-platform-…">
    <summary class="abstract__summary">
      <h2 class="abstract__heading">
        <span class="abstract__title">LZ Oracle: an AI-assisted knowledge retrieval platform…</span>
        <span class="abstract__people">Maris Arthurs, Jeonghwa Kim, Ibles Olcina</span>
      </h2>
    </summary>
    <div class="abstract__body">{% capture abstract_md %}LUX-ZEPLIN (LZ) is the world's…{% endcapture %}{{ abstract_md | markdownify }}</div>
  </details>
```

Three constraints drive this shape:

- **`<summary>`'s content model is phrasing content *or* one heading element.**
  Two sibling elements inside `<summary>` would be invalid, so the title and
  byline are spans wrapped in a single `<h2>`. The `<h2>` also preserves a
  document outline now that the sidebar TOC is gone, and it becomes the
  disclosure control's accessible name ("title, byline"), which is what a
  screen-reader user needs to decide whether to open it.
- **The `id` lives on `<details>`, not the `<h2>`.** `document.getElementById(id)`
  then yields the element to open. Putting it on the heading would work too
  (`closest('details')`), but the wrapper is also the scroll target and the
  `scroll-margin-top` box, so one element carries both jobs.
- **No `aria-expanded` on `<summary>`.** Browsers already map `<details>`/
  `<summary>` to a disclosure widget and announce the open state. A hand-written
  `aria-expanded` would have to be kept in sync by JS and would break the no-JS
  path in Story 7.

`title` and `people` pass through `esc()` (`:433`), which escapes `& < > "`.
They are text nodes inside spans, never attribute values, so that is sufficient.

The `id` value is `talk._anchor`, already slugified by `slugify()` and
deduplicated per page with `-2`/`-3` suffixes in `assignAnchors()` (`:418-421`).
It needs no further escaping.

### 3. Entry markup — static (no abstract)

For an entry with an empty or whitespace-only `infoMd`:

```html
  <div class="abstract abstract--static" id="askalcf-a-rag-assistant-for-hpc-user-support">
    <h2 class="abstract__heading">
      <span class="abstract__title">AskALCF: A RAG Assistant for HPC User Support</span>
      <span class="abstract__people">Jingyan Jiang, Huihuo Zheng, …</span>
    </h2>
  </div>
```

Same `id`, same heading contract, no disclosure control — Story 4. This is not
an edge case in practice: at the time of writing, most entries in
`pages/program/abstracts/talks.md` have a byline and no description.

`collectAbstracts()` already normalizes a missing description to `''`
(`:567`), so the branch condition is `entry.infoMd.trim()` — which also covers
the whitespace-only criterion in Story 4.

An entry with an abstract but no People renders collapsible with the
`.abstract__people` span omitted entirely, not emitted empty (Story 1).

### 4. Markdown bodies

The body reuses the pattern at `:465` verbatim in spirit:

```js
`<div class="abstract__body">{% capture abstract_md %}${escLiquid(e.infoMd)}{% endcapture %}{{ abstract_md | markdownify }}</div>`
```

Why this and not `escMd()` + raw Markdown:

- kramdown does not process Markdown inside block-level HTML unless the element
  carries `markdown="1"`. Wrapping each abstract in `<div class="abstract__body">`
  would silently render the Markdown as literal text.
- `escLiquid()` (`:442-445`) escapes `& < >` *and* neutralizes `{` to `&#123;`,
  so sheet content can never execute a Liquid tag or filter — Story 2's
  "literal text, not executed" criterion. kramdown decodes the entities back to
  literal characters when it renders.
- `markdownify` runs the same kramdown configured in `_config.yml`, so abstracts
  render identically to the rest of the site — Story 2.

Reusing one capture variable name (`abstract_md`) across every entry on a page
is safe: Liquid evaluates in document order and each capture is consumed by the
`{{ … }}` immediately following it. `renderSession()` already relies on this
with `session_info_md` across every session on the schedule page.

`escMd()` loses its last caller and is deleted rather than left as dead code.

### 5. Toolbar

```html
<div class="abstracts__toolbar" hidden>
  <button class="abstracts__toggle-all" type="button">Expand all</button>
</div>
```

Rendered `hidden`; `abstracts.js` removes the attribute on init. Without JS the
control never appears and never lies about what it can do — Story 7. `type="button"`
prevents any form-submission default.

The button's state is communicated by its **label text only**, not
`aria-expanded`. `aria-expanded` describes a button that controls one region;
this one controls many, and the label is what a screen reader announces on
focus. When every collapsible entry is open the label reads "Collapse all",
otherwise "Expand all" — recomputed on every `toggle` event so individual
toggling keeps it honest (Story 5, final criterion).

The toolbar is omitted entirely when a page has no collapsible entries — a page
of all-static rows has nothing to expand.

### 6. `assets/js/abstracts.js`

Dependency-free; no jQuery, no Bootstrap, no Alpine. Roughly:

```js
(function () {
  var root = document.querySelector('.abstracts');
  if (!root) return;
  var panels = root.querySelectorAll('details.abstract');

  // 1. Deep links (Story 3)
  function reveal() {
    var id = decodeURIComponent(location.hash.slice(1));
    if (!id) return;
    var el = document.getElementById(id);
    if (!el || !root.contains(el)) return;
    if (el.tagName === 'DETAILS') el.open = true;
    el.scrollIntoView();
  }
  reveal();
  window.addEventListener('hashchange', reveal);

  // 2. Expand / collapse all (Story 5)
  // 3. beforeprint / afterprint (Story 6)
})();
```

Notes on each job:

- **Deep links.** Arriving from the schedule is a cross-document navigation, so
  the browser performs its own fragment scroll before this script runs; the
  SmoothScroll instance in `assets/js/app.js:34` (`a[href*="#"]`) only
  intercepts *clicks*, so it is not involved on arrival. Opening the target does
  not move the target — content expands below the summary row — so the explicit
  `scrollIntoView()` is there to re-settle the position and let
  `scroll-margin-top` apply, not to correct a shift. Static (`<div>`) targets
  fall through to the same scroll, satisfying Story 4's deep-link criterion.
  `root.contains(el)` guards against a fragment that matches some other element
  on the page.
- **Expand / collapse all.** Sets `.open` on every `details.abstract`, then
  relabels. A single `toggle` listener bound per panel recomputes the label so
  the control tracks state changed by any means.
- **Print.** `beforeprint` records each panel's `open` value, opens all;
  `afterprint` restores from that record — Story 6. This is JS-driven because
  CSS-only expansion of a closed `<details>` is not reliable across engines; the
  `@media print` rule in the stylesheet is a fallback, not the mechanism. The
  toolbar is hidden in print by CSS, since JS has by then removed its `hidden`
  attribute.

### 7. `assets/css/abstracts.css`

Follows the three conventions documented in `assets/css/program.css:1-21`:

- **Scoped token block on `.abstracts`**, mirroring program.css's palette so the
  two program surfaces read as one system: `--abstract-accent: var(--us-rse-main)`,
  ink `#4a4a4a`, strong `#363636`, muted `#757575`, hairline `#dbdbdb`, wash
  `#f4ecf1`. A separate sheet rather than an addition to `program.css` because
  program.css's tokens are scoped to `.program` and it loads only on the
  schedule page; duplicating six declarations is cheaper than restructuring it.
- **Targeted theme neutralization.** These pages render inside the theme's Bulma
  `.content` wrapper (`_layouts/page.html:9`), whose typography beats any
  single-class rule. Unlike program.css, the reset here must be *narrow*: the
  `.abstract__body` contains real prose, so `.content`'s `p`/`ul`/`ol` margins
  are wanted there. Only `.abstracts .abstract__heading` (which must out-rank
  `.content h2`'s size/weight/color) and the wrapper-level margins are reset.
- **Padding for spacing**, so no component rule has to out-rank the reset.

Component specifics:

- `.abstract__summary { list-style: none }` plus
  `.abstract__summary::-webkit-details-marker { display: none }` suppresses the
  default triangle; a chevron is drawn as a `::before` on the summary and
  rotated under `.abstract[open] > .abstract__summary`. `cursor: pointer`.
- Hover and `:focus-visible` on `.abstract__summary` follow the accent-on-hover
  idiom of `.program-nav__pill` (`program.css:108-112`). A visible focus ring is
  required by Story 2.
- `.abstract__title` is the strong ink at `.content h2` scale but tighter;
  `.abstract__people` is muted, smaller, on its own line — the '25 layout, in
  this site's type scale.
- `.abstract--static` renders the same heading with no chevron and no pointer
  affordance, visually quieter so it reads as "nothing to open here".
- `.abstract` rows are separated by a hairline `border-top` on `.abstract + .abstract`,
  matching `.session + .session` (`program.css:228-232`).
- `scroll-margin-top: 5rem` on `.abstract`, the same navbar clearance
  `.program-day` uses (`program.css:120`) — Story 3.
- `@media (max-width: 40rem)` reduces the summary padding and lets the byline
  wrap, consistent with program.css's breakpoint.
- `@media print` hides `.abstracts__toolbar` and the chevron, drops hover
  affordances, and includes the belt-and-braces
  `.abstract > .abstract__body { display: block }`.

### 8. Interactions with existing site behavior

- `assets/js/app.js:103-113` injects permalink icons into headings inside
  `.page__content`. These pages use `.content` (from `_layouts/page.html:9`), so
  no icon is injected into `.abstract__heading` — no interaction.
- Gumshoe (`app.js:43-60`) only initializes when `nav.toc` exists. Dropping
  `menubar_toc` removes it from these pages, so the scrollspy no longer runs
  there.
- `_includes/toc.html` is no longer included on these pages, so its
  `split: '<h'` parsing never sees the summary-nested `<h2>`. (Had the TOC been
  kept, the `<h2>` would still have been found, but its `id` would have needed
  to move back off the `<details>`.)
- The site-wide Bootstrap bundle (`_includes/footer-scripts.html:5`) is
  irrelevant here — nothing in the new markup uses `.collapse` or
  `data-toggle`.

### 9. Edge cases

| Case | Behavior |
| --- | --- |
| Entry has description, no People | Collapsible; `.abstract__people` omitted. |
| Entry has People, no description | Static `<div>` row (§3). |
| Entry has neither | Static row, title only. Reachable only if the sheet has an Event Title with a page format and nothing else. |
| Description is whitespace only | Treated as absent (`.trim()`). |
| Description contains `<script>` or `{% … %}` | Escaped by `escLiquid()`; renders as literal text. |
| Duplicate titles on one page | Already handled upstream by `assignAnchors()`'s `-2`/`-3` suffixes; ids stay unique. |
| Page has zero collapsible entries | Toolbar omitted; page is a plain list of static rows. |
| A format disappears from the sheet | `writeAbstractPages()` (`:618-627`) prunes the banner-carrying page and `writeMenubar()` updates the menu — unchanged. |
| Generator re-run on unchanged input | `writeIfChanged()` reports `unchanged`; the Liquid cache-buster keeps bytes stable. |
