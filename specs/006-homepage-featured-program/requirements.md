# Requirements — homepage featured program

Status: approved

## Summary

The homepage (`index.html`) today shows a banner, the `cards.html` call-to-action
grid (driven by `_data/cards/home.yml` via `cards: home` front matter), the
sponsor tiers, and the paginated news list. Nothing on it surfaces the program
itself — the keynote, in particular, is only reachable through the Program
menu at `program/keynotes/`.

The keynote page (`pages/program/abstracts/keynotes.md`) is generated by
`scripts/build-program.js` and carries a `do not edit` banner, so it cannot be
reused on the homepage by hand. But the same data is already exposed to Liquid:
`_data/program.json` (`site.data.program`) holds `days[].slots[].sessions[].talks[]`,
and every event carries `title`, `speakers`, `format` (raw sheet cell, e.g.
`Keynote`, `Student`), `infoMd` (the abstract/bio Markdown), an optional
`image` (e.g. `/assets/img/perez.jpeg`), and an `href` into its abstract page
(e.g. `program/keynotes/#fernando-p-rez`). The enclosing slot and session carry
the date, start/end time, and room.

This feature adds a reusable Jekyll include, `_includes/featured-program.html`,
that selects events from `site.data.program` by Event Format and renders them as
a featured block — portrait, name/title, when and where, a short excerpt, and a
link to the full abstract. The homepage includes it once for keynotes; the same
include can be dropped in again with another format (e.g. `Student`) without
new code. It is pure Liquid over committed data: no change to
`scripts/build-program.js`, `_data/program.json`, or any generated page.

## User stories

### Story 1 — Keynote featured on the homepage

As a prospective attendee landing on the homepage, I want to see who is
giving the keynote, when, and where, so that I know about the headline event
without digging through the program menu.

**Acceptance criteria**

- WHEN the homepage is built and `site.data.program` contains at least one
  event whose `format` is `Keynote`, THE system SHALL render a featured
  section on the homepage listing each such event.
- WHEN the featured section is rendered, THE system SHALL place it after the
  `cards.html` grid and before the "Conference Sponsors" header, under the
  heading "Keynote Speaker".
- WHEN a featured event has an `image`, THE system SHALL render it as a
  portrait through `relative_url` with an `alt` derived from the event title.
- WHEN a featured event has no `image`, THE system SHALL render the entry
  without a portrait and without a broken `<img>`.
- WHEN a featured event is rendered, THE system SHALL show its `title`, its
  `speakers` when non-empty, the day label and weekday of its day, the slot's
  `start`–`end` time, and the session `room`.
- WHEN a featured event has non-empty `infoMd`, THE system SHALL show a
  plain-text excerpt of it — Markdown rendered, HTML stripped, truncated to a
  word count of 40 — never the raw Markdown.
- WHEN a featured event has an `href`, THE system SHALL link its title and a
  "Read more" link to `href` through `relative_url`.
- WHEN a featured event has no `href`, THE system SHALL render its title as
  plain text and omit the "Read more" link.
- WHEN several events match, THE system SHALL list them in `program.json`
  traversal order (day → slot → session → event), i.e. chronological.

### Story 2 — Reusable for other formats

As a site maintainer, I want to feature other program elements (student
program, plenaries, workshops) with the same snippet, so that highlighting a
track is a one-line include rather than new markup.

**Acceptance criteria**

- WHEN the include is called with a `format` parameter, THE system SHALL select
  events whose `format` matches it case-insensitively and ignoring surrounding
  whitespace — the same rule `normalizeFormat()` uses in `build-program.js`.
- WHEN the include is called with a `title` parameter, THE system SHALL render
  it as the section heading; WHEN `title` is omitted, THE system SHALL render no
  heading.
- WHEN the include is called with an optional `limit` parameter, THE system
  SHALL render at most that many matching events.
- WHEN the include is used twice on the same page with different formats, THE
  system SHALL render two independent sections with no duplicated `id`
  attributes.
- WHEN no event matches the requested format, THE system SHALL render nothing —
  no heading, no empty wrapper — so the homepage degrades cleanly before the
  program is published or after a format is removed from the sheet.

### Story 2b — Student & Early Career featured on the homepage

As a student or early-career attendee, I want the student track highlighted on
the homepage, so that I can find the sessions aimed at me.

**Acceptance criteria**

- WHEN the homepage is built and `site.data.program` contains at least one
  event whose `format` is `Student`, THE system SHALL render a second featured
  section, headed "Student & Early Career Program", immediately after the
  keynote section and before the "Conference Sponsors" header.
- WHEN student events are rendered, THE system SHALL apply every Story 1
  per-event criterion (portrait optional, time/room, 40-word excerpt, link to
  `href`) unchanged.
- WHEN a student event sits in a muted session (e.g. the Mentor/Mentee Lunch
  inside "Lunch Break"), THE system SHALL still list it; selection is by Event
  Format only.

### Story 3 — Stays in sync with the sheet

As a program committee member, I want the homepage feature to update when the
program is rebuilt from the sheet, so that the homepage never contradicts the
program pages.

**Acceptance criteria**

- WHEN `scripts/build-program.js` rewrites `_data/program.json`, THE system
  SHALL reflect the change on the homepage at the next Jekyll build with no
  further edit.
- WHEN the feature is implemented, THE system SHALL NOT modify
  `scripts/build-program.js`, `_data/program.json`, or any file under
  `pages/program/abstracts/`.

### Story 4 — Looks at home on the site

As a visitor on a phone or desktop, I want the featured block to match the
site's existing look, so that it reads as part of the homepage.

**Acceptance criteria**

- WHEN the featured section is rendered, THE system SHALL style it from a
  stylesheet under `assets/css/` rather than inline `style=` attributes.
- WHEN the viewport is narrow (the existing `abstracts.css` mobile breakpoint),
  THE system SHALL stack the portrait above the text with no horizontal scroll.
- WHEN `bundle exec jekyll build` runs, THE system SHALL build without Liquid
  errors or warnings introduced by the include.

## Out of scope

- Any change to `scripts/build-program.js`, `_data/program.json`, or the
  generated abstract pages.
- Rendering the full abstract/bio on the homepage; the excerpt links out to the
  abstract page for that.
- Selecting events by anything other than Event Format (e.g. a hand-picked list
  of titles, a new "Featured" sheet column).
- A carousel, rotation, or other JavaScript behavior.
- Restyling `cards.html`, the sponsor section, or the news list.
- Featuring posters (they live on a separate sheet tab and have no schedule
  slot).

## Resolved decisions

- **Placement.** One featured area after the `cards.html` grid and before the
  "Conference Sponsors" header.
- **Formats at launch.** `index.html` calls the include twice, in this order:
  `format="Keynote"` with heading **Keynote Speaker**, then `format="Student"`
  with heading **Student & Early Career Program**.
- **Excerpt.** 40 words.
- **Verification.** This repo has no `tests/` directory or pytest suite, so the
  skill's `pipenv run pytest tests/unit/schedulernew` gate does not apply. Each
  task is verified instead by `bundle exec jekyll build` succeeding and a grep
  of `_site/index.html` confirming the expected markup.
